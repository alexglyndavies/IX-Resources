    Graphs¶

    By Linden Disney-Hogg

    In the following notebooks, we will delve into the topic of graph neural networks. But to do so, we first have to understand the data that GNNs deal with. So, what are graphs?

    Here, we will cover some of the basics, including essential terminology and Python toolkits. For an easy-to-read deep dive into graph theory, I recommend the book Introduction to Graph Theory by Robin J. Wilson.

    The essential Python library needed for dealing with graph data is networkx. You can find more tutorials on their homepage.

    Before getting going let's make an incomplete list of areas where graphs arise in the 'real' world (can you think of how they appear in your field):

    • logistics (route planning)
    • social networks (identifying cliques, influence)
    • computer science (page ranking, traffic routing, dependency graphs)
    • chemistry (compund structure identification, e.g. alkanes as trees)
    • biology (DNA and protein structure)
    • mathematics (simplicial complexes, dynkin diagrams, tropical curves)
    • linguistics (semantic networks, e.g. for bias analysis)
    • physics (Feynmann diagrams)

    I asked ChatGPT to read everyone's research expertise and describe how graph theory applies to their work, perhaps you are included and did not expect it? See the appendix for that output.

    As they have been a subject of intense study over many centuries, there are often exceptionally efficient algorithms for computing with graphs: if you can frame a problem you have as a graph problem, you will likely have luck in solving it (at least heuristically) rather efficiently.

    As a first example, let's look at the famous problem which kicked off the study of graph theory in 1736: the Königsberg bridge problem. Looking at the map below, can we visit every part of the town crossing each bridge exactly once? Euler turned the problem into one in graph theory, and proved that such a path exists iff the degree of each vertex in the graph is even. We will define these terms and more soon, but first we just use networkx to construct and view the graph.

    Basic definitions¶

    At it's simplest, a graph $G$ is a set of vertices (also called nodes) $V$ and edges between these vertices $E$. We visualise them as above, with vertices represented by a point, and edges represented as lines between points.

    In [ ]:
    Copied!

    # Networkx uses the term nodes G.nodes(), G.edges()

    (NodeView((0, 1, 2, 3)),
 MultiEdgeDataView([(0, 1), (0, 1), (0, 2), (1, 2), (1, 3), (1, 3), (2, 3)]))

    Note how in the above each vertex gets a label $v$ (here the nonnegative integers) and an edge gets a label $(v, w)$ where $v,w$ are labels of the vertices joined by an edge. In an undirected graph we do not care about the ordering of the vertex labels in an edge, but in a directed graph (or digraph). A graph is simple if it has at most a single edge between any pair of vertices and it has no loops (edges from a vertex to iself). networkx calls a graph that is not simple a MultiGraph. We can also decorate edges with any dictionary of attributes: most commonly one assigns a weight (more later).

    We can also define the degree of a vertex to be the number of edges incident to it (for a directed graph one can talk of the in degree and out degree).

    Representations of graphs¶

    We have already seen one representation of a graph, its adjacency matrix $A = A(G)$. For a multidigraph, choosing an ordering of the vertices the entry $A_{ij}$ is the number of edges $i \to j$.

    Clearly if $G$ is a simple undirected graph then $A$ is a symmetric binary matrix with zeros on the diagonal. In this case the adjacency matrix is an inefficient way to store the information of the graph $G$. Moreover, if a graph is sparse, that is many entries of adjacency matrix are zero, then this representation is even more inefficient.

    That said, with simple undirected graphs the adjacency matrix allows us to perform some magic, for example $$ (A^l)_{ij} = \lvert \text{length-$l$ paths from $i$ to $j$} \rvert. $$

    An obvious point to make is that the choice of ordering of the vertices affects $A$, and permutating the vertices corresponds to conjugating $A$ by the associated permutation matrix.

    We can also describe graphs as "dicts of dicts of dicts" which is more efficient for large sparse networks. The keys are the vertices (which can thus be given any hashable label), and the corresponding values are themselves dictionaries describing the adjacency data of the vertex (i.e. what it shares an edge with and properties of that edge). Multigraphs go one depth of dictionary further.

    A path between two vertices $v, w \in V(G)$ is a collection of vertices $v = v_0, \dots, v_n = w$ (all $v_i$ distinct) such that each of the edges $(v_i, v_{i+1}) \in E$. We think of walking along the edges in the graph from $v$ to $w$. We say a graph is (path) connected if between every pair of edges there is a path. Disconnected graphs correspond to those whose adjacency matrix is, up to some permutation, block diagonal.

    A tree is a graph where between any two vertices there exists exactly one path (equivalently a connected acyclic undirected graph). Trees are an extremely useful concept to have clear in your mind because their structure can often give considerable performance improvement to algorithms ($O(n) \to O(\log n)$).     We say that two graphs are isomorphic if there is a way to relabel their vertices such there is a 1-1 correspondence between their edges. One can create isomorphic graphs easily by acting with a permutation upon the vertices of one, but in general telling if two graphs are isomorphic is hard. One can construct incomplete heuristics which are particularly relevant for GNNs.

    Weightings¶

    In our present example, entires of the adjacency matrix were a count of edges in a Multigraph. In this perspective, all edges are created equal.

    In practice one may wish to have varying weights for edges, which could model

    • resistivity in an electric circuit (electrical engineering)
    • travel time along a route (logistics)
    • proximity (when modelling DNA)

    and much more.

    To create such simple graphs with weighted edges we can just replace the values in the adjacency matrix with the weights of the edges.

    In [ ]:
    Copied! 
    # Construct the graph.
# We will construct using a weighted adjacency matrix.
# For simplicity I will perturb the previous one with some noise, then we treat
# the created graph not as a MultiGraph but simply a Graph.
adj_array = np.array([[0., 2., 1., 0.],
                      [2., 0., 1., 2.],
                      [1., 1., 0., 1.],
                      [0., 2., 1., 0.]])
noise = np.random.rand(4, 4)
noise = noise - np.transpose(noise)
noise = np.round(np.abs(noise), 1)
adj_array += 10*noise
G = nx.from_numpy_array(adj_array,
                        create_using=nx.Graph,
                        parallel_edges=False)

# Draw the graph.
edge_labels = nx.get_edge_attributes(G, 'weight')
nx.draw(G, pos=positions, node_size=500)
nx.draw_networkx_edges(
    G, pos=positions)
nx.draw_networkx_edge_labels(
    G, pos=positions, edge_labels=edge_labels)
plt.show()
